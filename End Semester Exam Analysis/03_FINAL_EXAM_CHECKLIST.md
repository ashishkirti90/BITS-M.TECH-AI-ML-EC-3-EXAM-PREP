## Paper scan - first 7 minutes

1. Check total questions, compulsory/choice instructions and marks.
2. Tag each question by topic/pattern.
3. Mark `M` if solvable from memory, `L` if one lookup is needed, `R` if calculation risk is high.
4. Write the subject watermark page beside every `L` question.
5. Start with the highest-confidence complete numerical or derivation, not automatically Q1.
6. Reserve 15-20 minutes for review.

## Time allocation

For a 150-minute, 40-mark paper, the raw budget is 3.75 minutes per mark. After a 7-minute scan and 18-minute review, the working budget is about **3.1 minutes per mark**.

| Marks | Target working time | Required visible work |
|---:|---:|---|
| 1-2 | 3-6 min | Definition/formula, direct answer, one reason |
| 3-4 | 9-13 min | Method, substitutions/reasoning, result, interpretation |
| 5-6 | 15-19 min | Full intermediate table/derivation and conclusion |
| 7-10 | 22-31 min | Complete multi-part solution, checks and justification |

If one subpart stalls, leave the governing formula and substitution, move on, and return. Correct method can earn marks even when arithmetic is unfinished.

## How to write for marks

### Numerical

`Given -> Required -> Formula/principle -> Substitution -> Intermediate calculations -> Final answer -> Interpretation`

- State the convention: variance denominator, log base, tie rule, margin width, gradient sum/mean or other ambiguity.
- Keep sufficient precision and round once at the end.
- Label tables and matrices; do not leave unexplained numbers.
- Sanity-check range, sign, units, dimensions and probability totals.

### Derivation

`Starting equation -> assumptions/constraints -> transformation -> key step explanation -> final expression -> verification`

### Conceptual or justify

`Definition -> mechanism -> scenario link -> trade-off/limitation -> conclusion`

### Comparison

Compare the same dimensions: objective, training mechanism, assumptions, strengths, limitations and use case. Avoid two unrelated definition paragraphs.

### Algorithm

`Input -> initialization -> repeated steps -> stopping condition -> output -> complexity/limitation if asked`

### Diagram/architecture

Label inputs, dimensions, transformations, learned parameters and outputs. Refer to the diagram in the prose.

## Open-book lookup rules

1. Solve from memory whenever possible.
2. Use the watermark for formula verification, long derivations, tables or worked examples.
3. Navigate by the verified **PDF-viewer page**, not an internal slide/page number.
4. Stop exploratory searching after about 30-40 seconds.
5. Never spend several minutes looking up a basic formula that should have been memorized.
6. When a key/source convention conflicts with the question, state the convention and verify against the givens.

## Subject submission checks

### ISM

- [ ] Hypotheses and significance level stated.
- [ ] Correct test and assumptions selected.
- [ ] Test statistic, degrees of freedom/critical value or p-value shown.
- [ ] Statistical conclusion translated into the question's context.
- [ ] Forecast/ANOVA/regression tables have totals and labels checked.

### ML

- [ ] Distance features scaled/typed correctly.
- [ ] Probability/weight/responsibility totals checked.
- [ ] SVM sign and half/full margin convention stated.
- [ ] Model recommendation addresses the scenario constraint, not only accuracy.
- [ ] Calculation ends with a class/cluster/deployment interpretation.

### DNN

- [ ] Tensor dimensions and parameter-count terms shown.
- [ ] Activation/loss/optimizer convention stated.
- [ ] Gate/attention weights checked for valid range or row sum.
- [ ] Architecture diagram labels data flow and shapes.
- [ ] Training-curve diagnosis connects symptom, cause and remedy.

### MFML

- [ ] Matrix/vector dimensions checked.
- [ ] Eigen/SVD/PCA ordering and normalization stated.
- [ ] Gradient/Hessian/sign arithmetic checked.
- [ ] Constraint feasibility and KKT conditions verified.
- [ ] SVM primal/dual variables and kernel assumptions labeled.

## Last 18 minutes

- [ ] Every compulsory question attempted.
- [ ] Every subpart visibly answered and labeled.
- [ ] Final answers boxed/underlined and units/classes stated.
- [ ] No probability, mixture weight or normalized weight total is invalid.
- [ ] No matrix/tensor dimension mismatch remains.
- [ ] No sign flip contradicts a stated class or direction.
- [ ] Assumptions and conventions are visible.
- [ ] Question numbers and continuation pages are correct.
